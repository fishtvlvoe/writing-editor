# 破例感官模組（po-li-gan-guan）

本模組為 `writing-editor` 的臉書短文專用骨架外掛。
底層 SSOT 與細節規範對齊：`~/.agents/skills/awesome-eason/companions/po-li-gan-guan/`。

## 核心零件（順序可打亂）

1. **破**：新聞或一句反差 → 立刻嘴替「你會問」 → 為什麼寫給你（不教戰、不捧名人）。
2. **例**：短鏡子 ＋ 具體畫面（不要履歷，停在畫面）。
3. **感**：藏在場景的身體記憶（95分不敢抬頭、被支配的恐懼、等下班裝死）。
4. **觀**：一篇只賣一句。所有的測試都是理解的過程。不討好巨人，重新去玩。

## Facebook 讀者結果

這個模組的文章目標，是讓 Facebook 讀者停留約 10～20 秒，從原本的 A 移到新的 B。

- 讀者可以跳著看；每小段可以獨立成立。空白與跳躍是呼吸，不要自動修順。
- 評估停留、分享、收藏與觀念轉變，不以論文式完整作為第一標準。
- 只在意思跑掉、事實錯誤或明顯誤植時修正；作者故意的不完全接順要保留。
- AI 負責查證、整理、提供結構；作者負責看見、觀點、情緒與最後口氣。

## 作者常用文體（未來優先沿用）

- 先讓讀者看見一個大家以為熟悉的現象，再翻出沒有被看見的那一層。不要在第一句直接公布答案，讓畫面走幾步後才反轉。
- 抽象觀點要掛在具體東西上：海邊、舞台、烤肉、禮物、ATM、馬車、便利貼、車程。例子不是裝飾，是讓讀者自己走到觀點。
- 文章可以用短句先定住讀者，再用兩三行的完整段落把理解往前推，最後回到口語短句落地。不要把編輯方便的斷行誤當成作者唯一的句型。
- 對照可以有，但不要複製句首。避免連續使用「前一次……／這一次……」、「不是……／不是……」或同一個列點開頭；改用不同的時間、主體、場景或語序自然轉換。
- 「不是……而是……」放在畫面之後使用，作為讀者已經看見例子後的翻面，不拿來代替破題。
- 公共事件寫到中段，要回到作者自己的生活經驗。新聞只負責打開題目，台南的距離、學習、工作或關係，才是作者真正的立場。
- 破不是直接公布答案，而是先製造讀者熟悉的畫面與缺口；例不是把人名排成清單，而是找一個能承擔問題的具體場景；感不是泛泛地說感動，而是說清楚作者為什麼被打到；觀不是漂亮總結，而是讓讀者多拿走一個看事情的判準。
- 不把文章收成完整說教。保留一點沒有講滿的空間，讓讀者自己接上最後一段看見；可以用「也許有一天，你也能看見我所看見的」這類開放式收束。

## 作者常用內容底座

以下是反覆出現的關心，不是每篇文章都要全部放入：

- 人不只是功能、技能或產出；方法可以換，人的方向、價值與想幫助誰不能被一起拿走。
- 資源分配本來就不平均。擁有較多資源的人，可以把機會、舞台與資訊帶到原本較難接觸的人面前。
- 讓別人被看見，不等於自己退讓；真正有影響力的人，能把自己的位置拿來讓更多聲音出現。
- 家不是設備、場館或地址，而是有人願意回來，也有人願意走進來；土地的意義要透過人與人的連結被看見。
- 公益不是因為「我有很多，所以分一點出去」，而是看見資源不對等後，願意把手上的東西帶到需要的地方。
