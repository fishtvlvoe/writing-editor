## Context

目前 repo 有一個老魚專用的 `agents/writing-assistant.yaml`，把作者稱呼、切角、心理轉譯與文章模組寫成固定設定；另有通用文章流程，但它以作者主筆為前提，沒有完整的初稿與修稿閉環。本案目標是讓**單一寫作助手 Agent**同時支援共通寫作流程與不同作者的個人偏好，不增加第二個面向使用者的角色。

專案模組慣例是：核心寫作流程放在根目錄 `SKILL.md)，特殊能力拆到 `skills/<module>/`，並登記在 `skills/manifest.md`。作者偏好與樣本屬個人資料，不能寫進共用 Agent/Skill 套件或提交到共享版控。

## Goals / Non-Goals

**Goals:**

- 將 `agents/writing-assistant.yaml` 改為中立、可供不同作者使用的單一入口。
- 讓核心 Skill 負責從一題一問訪談到作者確認定稿的完整文章流程。
- 讓作者可選擇建立、保存、查看、修改及刪除自己的風格設定；保存需明確同意。
- 將文章風格、平台差異做成可組合的作者偏好，不把任何一位作者的設定當成共通規則。

**Non-Goals:**

- 不新增另一個面向使用者的「責任編輯」Agent。
- 不在本案支援電子郵件、企劃書、報告等非文章類型。
- 不自動連結帳號、索取密碼、發布文章或保存單篇素材。
- 不把老魚個人設定、文章樣本或私有契約納入共享套件。

## Decisions

### 單一通用寫作助手 Agent，能力由 Skills 組成 (Keep one user-facing writing assistant; put capabilities in Skills)

`agents/writing-assistant.yaml` 是唯一面向使用者的入口；核心 Skill 管理對話流程，作者風格分析與平台格式則做成內部能力模組。既有 `agents/openai.yaml` 不在本案修改範圍，也不列為新系統的另一個角色。

**替代方案：**依訪談、風格分析或修稿拆成多個 Agent。否決原因是作者必須在不同角色間切換，重複提供上下文。

### 作者個人設定是私人且須主動同意保存 (Treat each author profile as private, opt-in data)

共用 Agent 與 Skill 不包含任何個人寫作檔案。作者看過風格摘要與示範改寫並明確同意後，才保存個人設定；作者可查看、修改或刪除。單篇主題、事實與草稿不會自動成為長期設定。

**替代方案：**將老魚的設定放入 Agent 預設提示。否決原因是會讓單一作者口吻污染所有使用者。

**待確認的實作選擇：**找出目標 Agent 執行環境支援的私人個人設定儲存方式，且該資料不得進入共用套件或版控。

### 風格分析是可跳過的首次使用路徑 (Make style analysis an optional first-use path)

Agent 提供兩種起點：使用者挑選代表文章，或授權分析指定帳號與時間範圍內可讀取的原創文章。帳號分析須取得明確同意；無法讀取的來源要明確告知，並請使用者貼上內容或提供匯出檔，不索取帳密，也不假稱讀取成功。

### 風格卡與示範改寫都要由作者確認 (Use an author-confirmed style card and rewrite)

Agent 先整理可觀察的文字習慣，再提供一段示範改寫。作者可以修正分析；只有明確同意後，才保存為個人設定。共通口吻可以附加選用的平台差異。

### 訪談與發想都保留作者決定權 (Preserve author agency during interviews and ideation)

Agent 每輪只問一個開放問題。作者卡住時，Agent 用開放提示協助思考，不列出預設答案。只有作者明確要求發想時才提供建議；建議須標示為靈感，作者確認後才能成為文章觀點。

### 第一版聚焦文章，不擴成萬用寫作工具 (Keep the first release focused on articles)

第一版支援社群貼文、部落格文章與網路文章。流程包含作者確認方向、必要的事實查證、大綱確認、起草與修稿、定稿前檢查及作者確認。發布是另一個動作，必須由作者明確要求。

## Implementation Contract

- **使用者看到的行為：**作者只需使用一個通用寫作助手；可選擇先建立個人風格設定，也可直接開始文章訪談。
- **資料形狀：**個人設定包含共通風格摘要與選用的平台差異；歸作者個人所有，不隨共用 Agent/Skill 發布。
- **帳號分析：**來源與時間範圍由作者指定；只分析可讀取且能確認為作者本人所寫的原創內容。讀取失敗時改用作者貼文或匯出內容。
- **失敗處理：**沒有樣本不會阻止寫作；讀不到的連結要標明未讀取；未保存的風格建議只供當次使用。
- **驗收方式：**用不同作者、不同平台、略過樣本、來源讀取失敗等情境驗證；確認每輪一題、方向與大綱先核准、修稿可回到前階段、定稿須作者核准且不會未授權發布。
- **範圍界線：**僅修改寫作助手 Agent、其核心 Skill、作者風格模組、必要的清單/範本及測試；其他 Agent 設定與無關文章模組不變。

## Risks / Trade-offs

- [社群平台限制帳號讀取] → 僅使用作者指定且可讀取的內容；讀取失敗就說明限制並提供貼上/匯出退路。
- [來源文章混合多種口吻] → 讓作者指定來源與時間範圍，並先審閱摘要與示範改寫。
- [個人設定誤入共享檔案] → 將設定放在私人儲存位置，並驗證不會被提交到共用版控。
- [開放訪談讓部分作者覺得太慢] → 共通預設仍是一題一問；只有作者明確要求時才提供發想建議。

## Migration Plan

1. 將老魚專屬規則從共用 Agent 預設移出，轉為可選的個人設定或專項模組。
2. 更新通用 Agent 與核心 Skill，不改動無關 Agent 設定。
3. 用不同作者設定與無個人設定兩種情境跑完整流程。
4. 若新流程驗收失敗，還原 Agent/Skill 共用檔案；不得覆寫作者既有私人設定。
