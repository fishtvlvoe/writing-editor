## Context

`po-li-gan-guan` 已定義破、例、感、觀四個文章零件，但現有核心流程把文章架構模組列為作者明確要求時才載入。這會讓助手跳過結構檢查，直接從素材進入初稿。

本案把四零件設為內部必要關卡。它是讀者旅程檢查，不是固定四段模板，也不是作者文風。每一篇文章都要說明讀者為何停下、如何看懂、如何和自己的處境連上、最後帶走什麼理解。

## Goals / Non-Goals

### Goals

- 在完整初稿前確認破、例、感、觀四個零件各自的任務、素材和限制。
- 缺料時回到一題一問，不用助手猜故事或補金句。
- 允許零件調整順序和合併段落，但保留內部結構記錄。
- 讓大綱能引用四零件檢查結果，作者能在全文前修正結構。

### Non-Goals

- 不固定四段、不要求平均分配篇幅。
- 不把四零件標籤輸出到公開文章，除非作者明確要求教學式標示。
- 不把任何作者的語氣、故事、例句或價值觀變成共用預設。

## Decisions

### Decision: Make the four-part structure gate mandatory before the full outline

訪談完成後、正式大綱前，助手建立四零件地圖。四個零件都要有任務和材料，才能進入大綱與初稿。這比把架構留成可選技巧可靠，因為上一輪測試已證明可選模組會被漏掉。

### Decision: Treat the four parts as reader tasks, not visible headings

破負責讓讀者停下，例負責讓讀者看懂，感負責連到讀者處境，觀負責留下新的理解。這四個任務可以分散在不同段落，不要求公開文章出現四個標籤。

### Decision: Missing material returns to interview instead of invention

如果例缺少具體材料，助手要問作者要不要提供真實場景、可查證來源或明確標示的假設例子；如果感或觀沒有作者確認的連結，也要用一題一問補齊。助手不能自己捏造人物經歷、情緒或結論。

### Decision: Ask for current-news integration before research

在查證前先問作者是否要把目前最新的時事新聞接進文章。作者拒絕時，文章只使用當篇素材和必要查證；作者同意時，先確認新聞範圍、時間、來源和要連到的觀點，再查找可靠來源。這能避免助手把新聞當成預設裝飾，也避免把作者沒有要求的時事帶進文章。

## Implementation Contract

### Observable behavior

1. 每篇文章在完整初稿前都產生內部破例感觀地圖。
2. 地圖列出四個零件的讀者任務、目前素材、來源類型和未解問題。
3. 任一零件缺材料或任務不清時，助手停止進入完整初稿，改問一題補訪談。
4. 在查證前，助手會詢問是否要結合目前最新的時事新聞；回答不要時不抓新聞，回答要時先確認範圍再研究。
5. 四零件完整後，地圖會併入大綱供作者確認。
6. 公開文章預設不顯示四個零件標籤，也不固定四段。

### Data shape

內部結構地圖至少包含：

- `破`：讀者要停下來看的衝突、問題或關聯；
- `例`：人物、事件、動作、物件、對話、數據、查證資料或明確標示的假設例子；
- `感`：讀者的困惑、處境、代價、情緒或希望，以及它和例子的連線；
- `觀`：作者確認過的新理解、判準或看事情的方式；
- `來源與限制`：作者素材、外部來源、假設例子或尚未確認。

### Failure behavior

- 缺 `破`：詢問讀者為什麼要在意這件事。
- 缺 `例`：詢問可提供的真實細節、來源或是否使用明確標示的假設例子。
- 缺 `感`：詢問這件事會讓讀者承擔什麼、擔心什麼或重新理解什麼。
- 缺 `觀`：詢問作者希望讀者最後多帶走哪個判準或理解。
- 作者要求直接寫但四零件仍缺料：維持停止點，說明缺少哪個零件，不產生完整初稿。
- 作者未同意時事結合：不主動加入最新新聞或時事例子。
- 作者同意時事結合但範圍不清：先問範圍、時間或要連到的觀點，不直接抓一批新聞。

### Acceptance criteria

- 規格包含四零件完整、缺料退回、可調順序、不外顯標籤和不捏造素材情境。
- 規格包含時事結合同意、拒絕、範圍確認和查證前停止情境。
- 核心 Skill 和 manifest 都明確把結構關卡設為文章流程必要步驟。
- `po-li-gan-guan` Skill 的四零件定義和核心流程一致。
- `spectra validate mandatory-article-structure-gate` 通過，且沒有 Critical 或 Warning。

### Scope boundaries

本案包含文章流程關卡、四零件地圖格式、Skill 文件和驗收情境。

本案不包含新的資料庫、UI、外部發布、自動生成真實故事或作者個人設定遷移。

## Risks / Trade-offs

- 強制關卡可能讓短文流程變慢 → 允許四零件合併在同一段，但不能省略任務檢查。
- 例子不足時容易卡住 → 允許查證資料或明確標示的假設例子，禁止偽造親身經歷。
- 作者只想要快速改寫時可能不需要完整結構 → 文章仍先完成最小四零件檢查；純校對或一句話改寫不啟動完整文章流程。

## Migration Plan

1. 更新核心 Skill、manifest 和 `po-li-gan-guan` Skill。
2. 在驗收情境加入結構關卡缺料和通過案例。
3. 執行 Spectra、契約詞和防污染檢查。
4. 保留既有私人設定和文章草稿，不修改既有文章內容。
