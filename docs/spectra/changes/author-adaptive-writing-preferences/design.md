## Context

現有寫作助手已有文章流程和可選的作者風格設定，但還沒有規定新作者如何說出自己的偏好。Fish 的三庫資料提供設計參考：文體庫處理表達方式，語意庫處理可重用的判斷原則，語境庫保護當篇文章的事實。前兩者可以成為作者確認後的私人設定，第三者必須留在當篇文章。

限制：只有一個面向使用者的 Agent；共享 Skill 必須支援有樣本、無樣本和無法讀取帳號內容的作者；私人設定必須留在 repo 外；既有查證、大綱、修稿、定稿和發布邊界維持不變。

## Goals / Non-Goals

### Goals

- 每位作者第一次寫作都能啟動一套一題一問的偏好訪談。
- 沒有樣本時，可用當次主題的小段試寫和作者修改來校準。
- 作者完全控制哪些內容升格為長期偏好。
- 分開共用訪談協議、私人設定和當篇文章語境。
- 用白話說明和實際例句呈現偏好，不只使用抽象風格標籤。

### Non-Goals

- 不從文風推斷作者人格、政治立場或隱藏動機。
- 不把 Fish 的詞彙、故事、例句和三庫內容變成所有人的預設。
- 不增加社群帳號連接器、登入憑證處理或自動爬取。
- 不取代既有文章訪談、查證、大綱、修稿和定稿關卡。

## Decisions

### Decision: Use correction-led onboarding instead of a fixed style questionnaire

助手先問一題開放問題，再依當次主題產生一小段可修改的文字。這個方案比固定問卷更適合，因為問卷會把作者塞進系統預先準備的風格名稱；作者親自修改，才能提供真實語氣和判斷依據。

### Decision: Keep style and philosophy private, keep context local to the article

私人設定可保存作者確認過的表達偏好和可重用判準。人物、事件、數字、場景、來源和結論留在文章語境，不自動寫入私人設定。這個方案比單一不斷增長的記憶安全，因為能降低跨篇和跨作者污染。

### Decision: Require review plus explicit consent before persistence

助手保存前要展示偏好摘要、證據類型、適用範圍、限制和示範改寫。作者明確同意後才寫入私人檔案。這個方案能讓作者刪掉錯誤推論，也避免一次誤解影響往後每篇文章。

### Decision: Apply confirmed profiles once per new article, not re-interview every time

已有確認設定時，新文章直接載入，不重做完整訪談；作者明確要求調整時才重新校準。這個方案保留連續性，也不讓作者每次寫文章都重新付出設定成本。

## Implementation Contract

### Observable behavior

1. 沒有確認設定的新作者，在完整初稿前看到一題偏好訪談。
2. 作者可以略過，並在 neutral mode 繼續文章流程。
3. 沒有樣本的作者可以修改一小段根據當篇主題產生的文字，並檢視偏好摘要。
4. 保存前一定展示偏好內容、證據、適用範圍、限制和示範改寫。
5. 已確認設定會在下一篇文章載入；中斷或拒絕保存的內容不算已確認設定。
6. 當篇人物、數字、場景和事實不會自動進入長期設定。

### Data shape

私人設定使用 repo 外的 Markdown，包含：

- `共通口吻`：作者確認過的表達、對話和句子偏好；
- `思維判準`：作者確認過的內容價值、判斷和品質原則；
- `平台差異`：可選的平台寫法；
- `證據與限制`：每條規則是作者明說、修改示範或確認樣本，並記錄適用範圍。

文章語境則保存讀者、用途、事實、來源、例子、立場和未解問題，不自動附加到私人設定。

### Failure behavior

- 找不到設定：明確說明使用 neutral mode，繼續寫作。
- 作者略過：不寫入私人設定。
- 作者拒絕推論：刪除或修改候選規則，不當成已確認偏好。
- 設定路徑無法寫入或位於 repo 內：不保存，展示已審閱文字供本次使用。
- 帳號或來源讀不到：不假稱已分析，改用貼文樣本或試寫校準。

### Acceptance criteria

- 新 SR 規格包含一題一問、略過、續接、試寫校準、審閱、同意、重用和更新情境。
- 測試證明文章事實不會變成私人規則，且作者 A 的設定不會套到作者 B。
- `spectra validate author-adaptive-writing-preferences` 和 `spectra analyze author-adaptive-writing-preferences` 通過，沒有阻擋項目。
- 既有文章流程和作者設定驗收仍通過。

### Scope boundaries

本案包含共用訪談協議、作者偏好校準、私人設定欄位、文章語境隔離、驗收情境和 Skill 文件。

本案不包含帳號連接器、外部發布、UI 改版、新的持久化服務，以及既有私人 Markdown 以外的資料庫遷移。

## Risks / Trade-offs

- 一小段試寫可能讓規則過度貼近單一主題 → 標示證據有限，必要時請作者再修正一段，並把限制寫在審閱摘要。
- 作者可能沒看懂自己同意的規則 → 以白話描述和示範改寫呈現，再要求確認。
- 私人設定和文章語境可能混在一起 → 只有作者明確升格才能把文章內容變成長期偏好，並加入防污染情境。
- 不同平台有不同習慣 → 平台差異採選配，先套共通口吻，再套已確認的平台設定。

## Migration Plan

1. 將偏好訪談與三層邊界加入 `writing-editor` Skill 和 `author-style-profile` Skill。
2. 保持既有私人 Markdown 可讀；缺少的區段保持空白，不自動補造。
3. 執行情境測試、Spectra validate 和 analyze 後再提交。
4. 若訪談流程需要調整，可暫停啟動訪談，但保留私人設定格式和文章流程。
